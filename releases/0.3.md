# Release 0.3 — 결제 알림 파싱

## 상태

- 버전: `0.3.0`
- 상태: 구현 및 빌드 검증 완료
- 구현일: 2026-10-16

## 목표

Release 0.2에서 수집한 알림 원문을 보수적으로 판별하고, 명확한 결제 승인 알림에서 `PaymentCandidate`를 생성한다. 이 릴리즈에서는 후보를 실제 결제로 등록하거나 중복 여부를 판단하지 않는다.

## 구현 범위

- 명확한 `승인`, `결제 완료`, `사용` 문구를 포함한 알림 감지
- 승인 취소·결제 취소·환불 알림 제외
- 원화 금액 추출 및 원 단위 `Long` 변환
- 가맹점 후보 추출
- 알림에 포함된 결제수단 이름 추출
- 연·월·일·시각, 월·일·시각, 시각 형식 파싱
- 명시적인 결제 시각이 없으면 알림 수신 시각 사용
- 파싱 결과를 원본 알림 이벤트에 보존
- Release 0.2에서 저장된 기존 원문을 앱 시작 시 한 번 재파싱
- 알림 로그에서 결제 후보, 확인 필요, 결제 알림 아님 상태 표시

## 파싱 상태

| 상태 | 의미 |
|---|---|
| `CANDIDATE` | 금액과 가맹점을 확인해 결제 후보 생성 |
| `NEEDS_REVIEW` | 결제 알림으로 보이지만 금액 또는 가맹점을 확정하지 못함 |
| `NOT_PAYMENT` | 명확한 결제 승인 알림이 아니거나 취소·환불 알림 |
| `UNPROCESSED` | 아직 파서가 처리하지 않은 기존 이벤트 |

`CANDIDATE`도 아직 실제 `Payment`가 아니므로 월 사용금액에 포함되지 않는다.

## 데이터 변경

Room 데이터베이스 버전을 3에서 4로 올리고 `notification_events`에 다음 필드를 추가했다.

- `parseStatus`
- `parsedAmount`
- `parsedMerchant`
- `parsedPaidAt`
- `parsedPaymentMethod`
- `parseMessage`

마이그레이션 시 기존 원문은 `UNPROCESSED`로 보존한 뒤 앱에서 파싱한다.

## 보수적 처리 원칙

- 확인하지 않은 카드사별 전용 형식을 대량으로 추측하지 않는다.
- 명확한 결제 키워드가 없는 알림은 후보로 만들지 않는다.
- 원화 금액 또는 가맹점을 확정하지 못하면 `NEEDS_REVIEW`로 남긴다.
- 취소·환불 이벤트는 새 결제 후보로 만들지 않는다.
- 원문과 파싱 결과는 외부 서버로 전송하지 않는다.

실제 금융 앱마다 문구 형식이 다르므로 실기기에서 수집된 원문을 확인하며 파서 규칙을 보완해야 한다.

## 제외 범위

- PaymentCandidate의 실제 Payment 변환
- Push와 SMS 중복 판정 및 병합
- 기존 Payment와 후보 비교
- 확인 필요 후보를 확정하는 UI
- 취소·환불의 기존 결제 반영
- 카드사별 전용 Parser 대량 구현

위 기능 중 자동 등록과 중복 처리는 Release 0.4 범위다.
