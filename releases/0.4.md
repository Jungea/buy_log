## 구현 범위

- 파싱된 결제 후보를 실제 `Payment`로 자동 등록
- 알림에서 읽은 결제수단이 없으면 자동 등록 보류
- 결제수단 이름이 처음 발견되면 결제수단으로 자동 추가
- 금액·가맹점·결제수단·결제시각(5분 이내)을 기준으로 중복 후보 탐색
- 서로 다른 출처(Push/SMS)의 동일 후보는 HIGH로 기존 결제에 자동 연결
- 같은 출처끼리 또는 수동 결제와 겹치는 후보는 MEDIUM으로 보관
- 알림 로그에서 MEDIUM 후보를 `같은 결제` 또는 `별도 결제`로 확정
- 기존 0.3 후보도 앱 시작 시 자동 등록 처리

## 중복 정책

| 판정 | 처리 |
|---|---|
| HIGH | 기존 Payment에 SourceEvent를 자동 연결 |
| MEDIUM | 월 사용금액에 넣지 않고 사용자 확인 대기 |
| LOW | 새 Payment로 자동 등록 |

취소·환불 알림은 0.3 파서에서 후보로 만들지 않는다. 결제수단을 읽지 못한 후보도 자동 등록하지 않는다.

## 데이터 변경

Room 데이터베이스를 4에서 5로 올리고 `notification_events`에 다음 필드를 추가했다.

- `registrationStatus`
- `duplicateConfidence`
- `paymentId`
- `suggestedPaymentId`
